# unity-asset-library

A live, auto-updating catalog of my Unity Asset Store purchases. This repo
holds the data and a viewer page — it's never edited by hand, it's kept in
sync automatically by a companion Firefox extension.

## How it works

```
Unity Asset Store          Firefox extension            This repo              Netlify
(buy/add an asset)  --->   (Unity Asset Logger)   --->   library.json   --->   auto-deploy
                            detects it, stores it          index.html          (live site +
                            locally, pushes here                               JSON endpoint)
```

1. The **Unity Asset Logger** Firefox extension watches assetstore.unity.com
   and detects the moment a package becomes yours (free or paid).
2. It stores captures locally, then pushes the full library to this repo as
   `library.json` via GitHub's Contents API — either on a daily timer, or
   immediately if you click "Sync now" in the extension's popup.
3. Netlify is connected to this repo (auto-deploy, no build step, publish
   directory = repo root) and redeploys automatically on every push.

## Files

- **`library.json`** — the actual data. An array of asset objects (see
  schema below). Fully regenerated on every sync — don't hand-edit it,
  changes will just get overwritten by the next push.
- **`index.html`** — a static, searchable viewer for the library. No build
  step, vanilla JS. Reads `library.json` from the same directory at
  runtime, so it always reflects the latest sync once Netlify redeploys.
- **`seed-library.json`** — a one-time seed export used to bootstrap the
  extension with pre-existing catalog history when first setting this up.
  Only needed again if setting up on a fresh install — see below.

## Data schema

Each entry in `library.json`:

| Field | Meaning |
|---|---|
| `id` | Internal unique ID, generated by the extension |
| `publisher` | Asset Store publisher name |
| `asset` | Package name |
| `category` | Free-text category (editable in the extension popup) |
| `purpose` | One-line description (only present on seeded/historical entries) |
| `tags` | Comma-separated tags (editable in the extension popup) |
| `size` | Package size, if known |
| `purchaseDate` | Acquisition date (`YYYY-MM-DD`) |
| `lastUpdated` | Publisher's last-updated date, if known |
| `version` | Package version, if known |
| `url` | Asset Store product page URL, if captured live |
| `status` | `Active` or `Deprecated` |

Newer, live-captured entries only populate `category`, `tags`, `url` from
what's scrapable off the product page — `purpose`/`size`/`lastUpdated`/
`version` are blank unless filled in manually or merged in from a fuller
export later.

## Commit message format

`<trigger>: <total> total (<delta>) — last updated <timestamp UTC>`

- **trigger**: `Auto sync` (daily timer) or `Manual sync` (popup button, or
  a library import)
- **delta**: `+N new`, `-N removed`, or `no count change` since the
  previous successful push — a net change, not a breakdown of individual
  adds/removes in that window

Example: `Auto sync: 324 total (+3 new) — last updated 2026-09-22 08:00 UTC`

## Setting up from scratch (new machine, lost token, etc.)

1. **Generate a token**: GitHub → Settings → Developer settings →
   Personal access tokens → Fine-grained tokens → restrict to this repo
   only → Permissions → **Contents: Read and write**. Nothing else.
2. **Install the extension**: get the latest signed `.xpi` → Firefox →
   `about:addons` → gear icon → Install Add-on From File. On Android:
   Settings → About Firefox → tap the logo 5× → Settings → Install
   Extension from File.
3. **Configure it**: extension popup → Settings → enter this repo's
   owner/name, `library.json` as the path, `main` as the branch, and the
   token from step 1. Add the Netlify site URL too.
4. **Restore history** (only if starting fresh, i.e. `library.json` here
   is empty or missing): Settings → Import existing library →
   `seed-library.json` from this repo.
5. **Netlify**: if setting up a new site, netlify.com → New site → Import
   from Git → this repo → no build command, publish directory = repo
   root → Deploy.

## Notes

- The repo can be public or private — Netlify authenticates to GitHub
  separately during its own setup, so a private repo doesn't block
  deployment. Only the *deployed Netlify site* needs to stay open if you
  want the JSON endpoint reachable without credentials.
- Paid-purchase detection and multi-item checkouts have known limitations
  — see the extension's own README for details. The short version: if
  something you bought doesn't show up, just revisit that asset's page
  once and it'll get backfilled automatically.
